# Artifact: GitHub Portfolio & Release Engineering Plan (v0.3.1)

## Purpose
This document details the release engineering, Git tagging taxonomy, and portfolio presentation strategy for FolioLingo.

---

## 1. Release Milestone Map

| Version Tag | Release Type | Focus Area | Key Deliverables |
|:---|:---|:---|:---|
| `v0.1.0` | Initial Alpha | Core Reader Canvas | Tokenized reading canvas, dual-sentence alignment, local lexicon lookup, library catalog. |
| `v0.2.0` | Beta Release | Persistence & Social | Firebase Firestore cloud sync, vocabulary notebook with spaced-repetition status, habit streaks, social league. |
| `v0.3.0` | Feature Release | Performance & Quizzes | Two-tier breakdown latency split (`ThinkingLevel.LOW`), 12-language base pairing, chapter quizzes, trademark scrubbing. |
| `v0.3.1` | Portfolio Release | Documentation & Polish | Comprehensive portfolio README, ASCII system diagrams, development guides, process artifacts archive. |

---

## 2. Commit Staging Strategy
- Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `perf:`)
- Clean commit messages with descriptive bodies.
- Annotated Git tags referencing release notes and milestone scope.

---

## 3. Remote Push Architecture
- Pre-configured `.gitignore` to prevent sensitive environment variable leaks.
- Verification via TypeScript compilation and automated linting before initial commit.
- Single-command remote setup for developers and portfolio reviewers.
