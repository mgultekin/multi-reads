# FolioLingo v0.5.0 — Product Owner Audit & Use-Case Catalog

**Release Tag**: `v0.5.0`  
**Role**: Product Owner & Lead Systems Architect  
**Scope**: Full-Application Audit, User Journey Remediation, SRS & Habit Integrity, and Firestore Reading Log Sync

---

## 1. Executive Summary of Product Audit

During the `v0.5.0` Product Owner audit of **FolioLingo**, we evaluated every user journey across the four core pillars (**Public Domain Library**, **Reader Studio**, **Wordbook SRS**, and **Habit & Scholar League**) and identified critical functional gaps that degraded long-term retention and data integrity:

1. **Gutenberg Manuscript Loading Dead-End**: Searching Project Gutenberg via Gutendex created book cards with placeholder text (`"Loading full text from Project Gutenberg..."`), and `ReaderView` never hydrated the full manuscript or bypassed browser CORS blocks.
2. **Ephemeral Reading Progress**: Advancing sections (`Next Section` / `Previous Section`) did not persist `currentChunkIndex` or `lastReadAt`, forcing readers back to Section 1 on reload and offering no "Continue Reading" affordance in the Library.
3. **Words Read vs. XP Conflation**: `App.tsx` routed both section word counts (`450 words`) and bonus XP (`+10 XP` for saving a word, `+25 XP` for passing a quiz, `+15 XP` for cloze recall) through `recordWordsRead()`, falsely inflating `wordsReadToday` and scaling quiz XP by `0.1`.
4. **Wordbook SRS & Unicode Cloze Failures**: Cloze fill-in-the-blank challenges used ASCII word boundaries (`\b`), failing whenever a Spanish, French, German, Italian, or Turkish word started or ended with accented characters (`ñ`, `é`, `ü`, `ş`, `ğ`, `ç`). Scoring a card also failed to update React state in-memory, and users had no way to filter cards due today or export their deck.
5. **Redundant Backend UI & Settings Desync**: The Scholar Hub exposed a legacy Supabase configuration tab even though the application is architected on **Firebase Firestore** (`/users/{uid}/reading_logs`), and `SettingsModal` only listed 7 of the 14 supported translation base languages while using iframe-blocked `window.confirm` / `alert` dialogs.

## 2. Formal Use-Case Catalog & Acceptance Criteria (`UC-01` – `UC-12`)

### Pillar I: Library & Content Discovery

#### `UC-01`: Browse, Filter, and Manage Multi-Source Literary Library
- **Primary Actor**: Language Learner / Scholar
- **Preconditions**: User has selected a target language (`es`, `fr`, `de`, `it`, `tr`, `en`).
- **Main Success Scenario**:
  1. User filters works by literary genre (`All Genres`, `Fiction`, `Philosophy`, `Science`, `History`, `Biography`, `Poetry`) and source (`All Sources`, `Curated Classics`, `Gutenberg`, `Wikipedia`, `Imported`).
  2. User can delete any imported (`custom`), Wikipedia, or fetched Gutenberg work via the card's trash icon without affecting curated seed classics.
- **Acceptance Criteria**:
  - [x] All 5 source filter tabs accurately partition library items.
  - [x] Deleting a custom or fetched book removes it from both IndexedDB and localStorage fallback state immediately.

#### `UC-02`: Search & Hydrate Full-Text Manuscripts from Project Gutenberg
- **Primary Actor**: Language Learner
- **Trigger**: User searches Gutenberg in `LibraryView` and opens a discovered book in `ReaderView`.
- **Main Success Scenario**:
  1. `ReaderView` detects the unhydrated Gutenberg placeholder (`Loading full text from Project Gutenberg...`).
  2. Client requests `GET /api/gutenberg/:id` on the Express server.
  3. Server fetches the UTF-8 manuscript from Project Gutenberg mirrors, strips legal header/footer boilerplate, and returns clean literary prose.
  4. `ReaderView` segments the text into ~550-word sections, updates `wordCount` and `estimatedReadTimeMinutes`, persists the hydrated book, and renders Section 1.
- **Acceptance Criteria**:
  - [x] Server proxy `GET /api/gutenberg/:id` resolves Gutenberg texts without browser CORS errors.
  - [x] Hydrated books persist across reloads so subsequent opens are instantaneous.

#### `UC-03`: Resume Active Manuscript via "Continue Reading" Shelf
- **Primary Actor**: Returning Reader
- **Main Success Scenario**:
  1. As the user navigates sections in `ReaderView`, `currentChunkIndex` and `lastReadAt` are saved to persistent storage.
  2. Returning to `LibraryView` displays a prominent **Continue Reading** callout banner for the most recently read book in the active target language, showing exact section progress (`Section X of Y`).
- **Acceptance Criteria**:
  - [x] Clicking `Resume Section X` opens `ReaderView` at the exact saved `currentChunkIndex`.

### Pillar II: Interactive Reader Studio

#### `UC-04`: Instant Contextual Word Lookup & Progressive Philology
- **Primary Actor**: Reader
- **Main Success Scenario**:
  1. Opening any section triggers `POST /api/gemini/batch-prefetch` to pre-cache sentence translations and top vocabulary in the background.
  2. Hovering a word for `80ms` triggers predictive word prefetching.
  3. Clicking any word opens `WordBreakdownPopover` with `0ms` latency on cache/lexicon hits or sub-300ms via `gemini-3.1-flash-lite-preview` (`ThinkingLevel.MINIMAL`).
- **Acceptance Criteria**:
  - [x] Saved words in the active deck are underlined in warm amber across the reading canvas.
  - [x] Changing the native translation language immediately re-translates the active popover.

#### `UC-05`: Toggle Bilingual Parallel Reading & Typeface Scale
- **Primary Actor**: Reader
- **Main Success Scenario**:
  1. User clicks the **Parallel** toggle in the Reader utility bar.
  2. Each paragraph displays its aligned native-language translation directly beneath the target-language prose using pre-cached sentence translations.
  3. User cycles typeface size (`Aa·SM`, `Aa·MD`, `Aa·LG`) and the preference persists in `UserProfile.readerFontSize`.
- **Acceptance Criteria**:
  - [x] Parallel translations render beneath each paragraph and update automatically when background batch prefetching completes.
  - [x] Font scale (`sm` | `md` | `lg`) persists across sessions and syncs with `SettingsModal`.

#### `UC-06`: Dynamic CEFR Level Adaptation (`A2` / `B1` / `B2` / `C1`)
- **Primary Actor**: Reader
- **Main Success Scenario**:
  1. User selects a target CEFR level in the Reader ribbon.
  2. System checks local IndexedDB `cefr_cache`; on miss, requests `POST /api/gemini/adapt-cefr` and caches the rewritten prose locally.
- **Acceptance Criteria**:
  - [x] Switching back and forth between `Original` and adapted CEFR levels resolves in `0ms` once cached.

#### `UC-07`: End-of-Section Comprehension Quiz
- **Primary Actor**: Reader
- **Main Success Scenario**:
  1. User clicks `Start Section Test` at the bottom of a section.
  2. User answers 3 contextual multiple-choice questions (Comprehension, Vocabulary, Nuance) in their native language.
  3. Completing the quiz awards `+25 XP` via `handleAwardXP(25)` without corrupting `wordsReadToday`.
- **Acceptance Criteria**:
  - [x] Quiz completion increments `profile.xp` by `+25` while leaving `profile.wordsReadToday` unchanged.

### Pillar III: Spaced Repetition Wordbook (`WordbookView`)

#### `UC-08`: Filter SRS Queue (`All Cards` | `Due for Review` | `Mastered`)
- **Primary Actor**: Learner
- **Main Success Scenario**:
  1. Learner switches between `All Cards`, `Due for Review` (`nextReviewAt <= now && masteryLevel < 5`), and `Mastered` (`masteryLevel >= 5`).
  2. Scoring a card (`Mastered (+10 XP)` or `Needs Practice`) updates both persistent storage and in-memory React state immediately.
- **Acceptance Criteria**:
  - [x] Mastery level (`Lvl X/5`) and queue counts update live without requiring a tab switch.

#### `UC-09`: Unicode-Safe Contextual Cloze Recall Challenge
- **Primary Actor**: Learner
- **Main Success Scenario**:
  1. Learner selects `Fill-in-the-Blank` mode.
  2. Target word is replaced with `[ ______ ]` using Unicode property escapes (`(?<![\p{L}])...(?![\p{L}])` with `giu` flags) so accented words (`español`, `être`, `für`, `città`, `güneş`) blank out reliably.
  3. Learner can request progressive letter hints, skip a card (`Skip`), or submit an answer (with diacritic-tolerant matching).
- **Acceptance Criteria**:
  - [x] Non-ASCII words are properly blanked in the context sentence.
  - [x] Correct answers award `+15 XP` via `onAwardXP(15)`.

#### `UC-10`: Export Vocabulary Deck to CSV / Anki
- **Primary Actor**: Learner
- **Main Success Scenario**:
  1. Learner clicks `Export CSV` in the Wordbook header.
  2. Browser downloads `foliolingo-wordbook-<lang>.csv` containing `Word, Translation, Lemma, PartOfSpeech, ContextSentence, SentenceTranslation, MasteryLevel`.
- **Acceptance Criteria**:
  - [x] CSV properly escapes quotes and UTF-8 diacritics for direct import into Anki or spreadsheet tools.

### Pillar IV: Habit Engine, Personal Analytics & Cloud Sync

#### `UC-11`: Verified Reading Log & Personal Analytics (`SocialLeagueView`)
- **Primary Actor**: Scholar
- **Main Success Scenario**:
  1. Advancing a section in `ReaderView` invokes `handleRecordWords(chunkWords, { bookId, bookTitle, language })`.
  2. `storageService.recordWordsRead()` increments `totalWordsRead`, `wordsReadToday`, and `wordsReadThisWeek`, creates a timestamped `ReadingLogEntry`, and syncs it to Firestore `/users/{uid}/reading_logs/{logId}`.
  3. Opening `Analytics & Log` in the Scholar Hub displays lifetime reading volume, SRS deck readiness (`due today` vs. `mastered`), daily goal progress, and the chronological list of verified reading sessions.
- **Acceptance Criteria**:
  - [x] `ReadingLogEntry` schema matches `firestore.rules` (`isValidReadingLog`: `id`, `userId`, `wordsCount`, ISO `timestamp`, `bookId`, `bookTitle`, `language`).
  - [x] Real user reading sessions appear at the top of the `Reading Feed` tab and in `Analytics & Log`.

#### `UC-12`: Unified 14-Language Preferences & Iframe-Safe Settings (`SettingsModal`)
- **Primary Actor**: User
- **Main Success Scenario**:
  1. User opens `SettingsModal` to configure display name, native language (all 14 `BASE_LANGUAGES`), default reader typeface scale (`sm` | `md` | `lg`), or daily word goal.
  2. User clears local CEFR cache via a two-step inline confirmation button without triggering browser `window.confirm` or `window.alert`.
- **Acceptance Criteria**:
  - [x] All 14 `BASE_LANGUAGES` are selectable in `SettingsModal`, `Navbar`, and `WordBreakdownPopover`.
  - [x] Zero usage of `window.alert`, `window.confirm`, or client-side API key inputs anywhere in the application.
